# Preregistration

The predictions, the designs and the analyses of all experiments were fixed before the runs they concern. This file
says what is frozen, how to verify it, and where each prediction is stated.

## Frozen files

`MANIFEST.sha256` lists every frozen file with its SHA-256, in the format of `sha256sum`:

- the protocol files: the configuration (`CONFIG.md`, `requirements.txt`), the validation rules
  (`VALIDATION_RULES.md`), the run protocol (`RUN_PROTOCOL.md`), the checker (`analysis/check_rules.py`,
  `analysis/real_rules.py`, `analysis/validate.py`), the analysis (`analysis/import_measured.py`,
  `analysis/load_data.py`, `analysis/schema.json`, `analysis/fmt.py`) and the table and figure scripts
  (`analysis/tables.py`, `analysis/figures/`);
- the LLM instance files (`m0/data/`) with their k_min shares and shortcut ceilings (`m0/results/`), and the
  instance-derived files of the controlled experiments (`e3/results/`);
- the code and run scripts that build the instances, train or query the models and compute the statistics (`m0/`,
  `e3/`, `pilot1/`), and the numeric checks of the theory (`theory_checks/`).

The training and test data of the controlled experiments (`e3/make_data.sh`) and the real-topology instances
(`m0/build_real.py`) are generated by the frozen code with fixed seeds and are therefore not listed. Result files are
outputs and are not listed. README files, this file, the license and `.gitignore` are not part of the manifest;
every other file of the release is, including `RELEASE_NOTES.md`, which lists how the released files differ from
those used for the runs.

The SHA-256 of `MANIFEST.sha256` itself is the value quoted in the paper:

    25bbf01c3f073079cd26b706dd82ee5c3e8115275d906e088ec0cc76155944aa

Verify both:

```bash
sha256sum MANIFEST.sha256        # must print the value above
sha256sum -c MANIFEST.sha256     # every listed file must be OK
# files present but not listed, minus the outputs of the runs (OUT); only README.md files, PREREGISTRATION.md,
# LICENSE, .gitignore and MANIFEST.sha256 may remain
OUT='(^|/)__pycache__/|^(m0/results/|m0/data/(e5_|e24_|e31[dhj]_)|e3/(data|data_nest|results|logs|ckpt)/|pilot1/results|results/'
OUT+='|analysis/figures/.*\.(pdf|values\.json)$|(DEVIATIONS\.md|env\.txt|gpu\.txt|validate_log\.txt)$)'
comm -13 <(cut -c67- MANIFEST.sha256 | sort) <(find . -type f ! -path './.git/*' | sed 's#^\./##' | sort) | grep -v -E "$OUT"
```

The outputs of the runs (OUT) are: everything in `m0/results/`, `e3/results/`, `results/` and `pilot1/results*`
that the frozen files do not already list; the generated data (`m0/data/e5_*`, `m0/data/e24_*`,
`m0/data/e31[dhj]_*`, `e3/data/`, `e3/data_nest/`); logs and checkpoints (`e3/logs/`, `e3/ckpt/`); the figures and
their recorded values in `analysis/figures/`; Python byte-code caches (`__pycache__/`); `DEVIATIONS.md`, `env.txt`, `gpu.txt` and `validate_log.txt`.

No listed file is modified while the experiments run.

## Predictions

| Set | Rules | Experiments | Where the criteria are stated |
|---|---|---|---|
| Protocol | V-B1 to B16, V-C1 to C21 | E0 to E10, E3, E3d | VALIDATION_RULES.md groups B and C; CONFIG §2 to §7 |

| 6 | V-C50 to C67 | E22 to E33 | CONFIG §6.14 |
| 7 | V-C68 to C74 | E34 to E36 | CONFIG §6.15; VALIDATION_RULES.md |

Each set was fixed before the runs of its own experiments; where a rule re-analyzes or compares with data of an earlier
set, it was fixed before that analysis. For every set, CONFIG §6 gives the reading of both outcomes. The paper's
appendix ("Preregistered Predictions") lists each prediction with its expected range and the outcome under which it
counts as falsified; `analysis/check_rules.py` decides every rule.

The E0 ALiBi test: X1 under NC, name-blind, the pilot's model, data, seeds 0-2, 8,000 steps, learning rate 1e-3, batch
size 32, ALiBi bias as the only change (`pilot1/run_alibi.sh`). Prediction: mean test accuracy >= 0.95. Falsified if
the mean stays below 0.80. Evaluation disables PyTorch's inference fast path, which mishandles a float attention mask
in eval mode (`pilot1/train.py`); with dropout 0, evaluation then equals the training-mode forward pass.

## Deviations

Every deviation from CONFIG.md or RUN_PROTOCOL.md (a different model revision, a rerun seed, a skipped step) is
recorded in `DEVIATIONS.md` with its date, reason and the results it affects.
